# Contribution-led Discussion

执行本技能时，把写作要求落实到论证、证据、句子和设计决定。完成用户请求的正文或修改；只列写作原则无法完成正文写作任务。

## 必读材料与适用范围

- 所有任务先读 [30 条操作要求与验收标准](references/requirements-checklist.md)。按条目修订，交付前逐项核对。
- 涉及本用户的博士论文、Void Monument、Chapter 6、四个 dimensions 或 B02–B08 时，继续读 [论文论证任务书](references/thesis-context.md)，读完本次涉及的维度。该文档决定案例为何出现、比较必须得到什么、理论承担哪一步，以及哪些设计事实需要查证。
- 涉及逐句修改、语言检查或首次完整写作时，读 [失败写法与修改示例](references/revision-examples.md)。用其中的判断方式检查文本，避免套用示例句。
- 通用任务沿用写作标准；其他研究使用自身的 contribution、证据、案例和章节安排。

## 起草前建立证据与论证记录

先读取用户提供的 Findings、Discussion 草稿、design records、Chapter 2/文献材料及真实章节标签。使用已有上下文；缺少会影响事实判断的材料时，只追问该缺项，继续完成已有证据支持的部分。

为本次正文内部建立以下记录，通常无需把记录表展示给用户：

| 记录项 | 必须写到的具体程度 |
| --- | --- |
| 已建立的 contribution | 写出本节需要解释的认识；本论文保留 situated design space 的完整表述。 |
| 参与者经验 | 编号、生活/空间条件、身体动作、感知对象、短原话、Findings 位置。 |
| 解释 | 说明从哪些细节推得哪一种关系；如 B06 的反复跪、摸、擦如何形成对表面的熟悉。 |
| 比较 | A 与 B 共享的问题、各自不同的关系，以及并置后增加的认识。 |
| 理论工作 | 文献中的确切主张、它解释的已识别关系、本研究在转译中继续处理的设计问题。 |
| 我的决定 | I interpreted/selected/kept/arranged 等动作及其具体对象、证据和理由。 |
| 访客层面 | 已实现的可见、可听、可接近或可操作条件；区分设计意图与实测反应。 |
| 尚缺证据 | 缺原话、设计记录、文献依据或标签时逐项记明；禁止用推测填满。 |

区分三种材料状态：已查证的研究事实；对话中保留、等待原始材料核对的案例；仅演示写法的设计句。后两种状态不能自动变成已实现功能或访客结果。技能内的案例说明不能取代 Chapter 5 和实际设计记录。

## 组织正文

以已形成的 contribution 为起点，解释其意义和适用范围。理论定位 contribution，参与者材料使它具体，比较产生新的认识，我的设计实践展示它如何运作。此顺序规定论证责任；段落可根据材料调整展开顺序。

每个维度的论证必须让读者找到以下内容，可分布在相邻段落中：

1. 本维度解决什么转译问题，以及它在整体 contribution 中的位置。
2. 足以理解该问题的参与者情境、动作、原话和 Findings 引用。
3. 明说比较所得；不能让读者从两个案例中自行猜出结论。
4. 理论为何在这里、解释了什么、本研究具体继续处理哪一步。
5. 我解释了什么、作了什么设计决定，以及该决定改变了何种访客接触条件。
6. 维度名称各部分为何适用，以及本研究增加的认识。

这些内容构成完整论证的检查项，禁止机械排成四套同样的六段。新论证可回调 Findings 中的材料；压缩时保留推理必需的情境、动作和原话，删除已完成的发现过程及无关背景。

## 句子与段落的硬要求

每个句子必须完成一项可识别的工作：提出明确主张、提供证据、解释证据、进行比较、定位理论、说明研究者行动或推进结论。逐句说明它接住上一句的哪一个内容、给下一句提供何种理由。只能靠作者心里补出的推理必须写出来。

每次使用 relationship、condition、meaning、experience、process、specific、particular 等词，检查它是否已有明确对象。证据允许说出视线、边界、触碰、表面、声音来源、房间、路线或许可动作时，直接说出。每次使用 this/these，核对读者能否唯一定位其指代。

段首须明确当前段落的分析任务。根据本段内容选择主张、经验问题、上一段的未完问题或研究者动作作为起点。检查连续段首及四个维度的展开方式，消除重复模板。不得通过随机替换连接词制造表面变化。

个人 PhD 中，分析、解释和设计决定使用 I/my。保留必要学术术语，并用案例及推理解释它们；删掉空泛学术包装。

## 三项禁止事项

### 防御性写作

禁止用 I do not claim、I am not suggesting、This should not be understood as、This does not mean、Rather than claiming，以及“我并不是要声称”“这不应被理解为”等句式预先回应假想质疑。直接写有证据支持的主张。真实局限应写明具体缺失、影响的判断和适用范围，放在合适的局限讨论位置。删除辩解时保留必要的不确定性。

### 过度野心与夸大贡献

禁止将本研究包装成 redefines embodied interaction、transforms participatory design、establishes a new paradigm、proves，或适用于全部 VR memory design 的普遍结论。每个 contribution claim 都要能落到本研究的案例比较、分析或具体设计决定。My study shows 后面仍可能接夸张内容，必须核对整个主张。写清研究实际识别或处理了什么。

### 否定前项再抬高后项的结构

全文禁止“不是……而是……”及语义同类结构：not X but Y、not merely/simply/just X but Y、not only X but also Y、rather than、instead of，以及“并非……而是……”“不仅……更是……”“与其……不如……”。less X than Y、beyond X to Y 在承担同类纠正对照时也须重写。拆成两句、使用破折号、或在下一句写 Rather/Instead，同样不能规避。

改写时直接陈述有效主张；若两件事都有实证价值，分别写出事实并解释关系。but/while/whereas 不得用于人为制造 tension。事实性的否定可以独立保留，例如参与者看不见边界。引号内原话必须准确；优先选择适用的短原话片段，禁止篡改原话来迎合句式要求。

上述禁令覆盖英文正文、中文对应段以及生成的解释性文字。文档中列出的禁用短语仅用于识别问题。

## 交付前检查与输出

先作论证检查，再作句子检查，最后作中英文及格式检查。依照 30 条验收标准处理每项：已满足、需修订、缺证据、本次范围不适用。缺证据项不可标为通过；需要在输出中简要注明。内部检查表通常不随正文输出，用户要求审查时再展示具体问题、原句、修改和原因。

必须回查：每个案例的 Findings 引用；每句原话的准确性；理论与研究贡献之间的具体关系；每个设计事实的依据；访客感受是否真的有评估证据；是否有遗漏的跨句推理；是否存在三项禁用修辞。

本博士论文延续已确定的 English → 中文逐段对应交付。英文应达到论文正文标准；中文自然呈现同样的实质论证。逐段核对主张、案例、引文、设计动作、推理、范围和确定性。中文中发现缺失的推理时，同时修复英文。其他任务按照用户指定语言；用户明确更改输出方式时遵循最新要求。

交付用户要求的完整范围。若用户要整节，完成整节；若用户要局部修改，保留相关上下文并修复受影响的衔接。不要用示范段落替代已请求的完整交付。
